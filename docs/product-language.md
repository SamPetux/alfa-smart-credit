# D03 — материал для согласования языка продукта

Подготовил Дмитрий. Согласование с Ильёй, Олегом и Игорем **не проведено**. Это вопросы и правила использования существующих контрактов, а не новые утверждённые тексты или изменение policy.

| Область | Канон / предлагаемое правило | Кто подтверждает |
|---|---|---|
| Статусы, команды и клиентские подписи | [statuses.json](../contracts/statuses.json): брать значения и client_labels напрямую, не создавать второй enum | Олег; Игорь — использование в UI |
| Risk input/output и причины | [risk-v1](../contracts/schemas/risk-v1.output.json): reason_codes, requested_fields, client_explanations и officer_explanations имеют разные назначения | Илья и Олег |
| Обязательные данные | [Risk input](../contracts/schemas/risk-v1.input.json), [OpenAPI](../contracts/openapi.yaml), [policy](../contracts/schemas/policy-v1.json): поля формы и обязательность submit согласовать с API, не путать с nullable данными внешних источников | Олег и Илья |
| Продукты, ставки, документы и альтернатива | Только policy-v1 и рассчитанный candidate; UI не считает заново и не увеличивает срок автоматически | Илья, Олег; Игорь — отображение |
| Суммы | В JSON string с двумя знаками, в домене Decimal; missing не равно нулю | Олег, Илья |
| Score | «Учебная оценка риска»; не вероятность одобрения и не решение сотрудника | Илья и Дмитрий |
| Кандидат / предложение | Кандидат формируется расчётом; предложение становится доступно клиенту после подтверждения сотрудника | Олег и Дмитрий |
| Ошибка источника / отказ | Техническая недоступность требует обработки/повтора, а не кредитного отказа | Олег и Илья |
| Подпись и выдача | Явно «имитация»/«смоделировано», без юридической подписи и перевода средств | Дмитрий и Игорь |

Вопросы Илье: соответствуют ли имеющиеся объяснения каждой причине; что может исправить клиент; как объяснять меньшую сумму без обещания одобрения? Вопросы Олегу: какие planned endpoint ещё не реализованы, согласованы ли DTO/allowed_actions и текущие переходы с каноном? Вопросы Игорю после появления экранов: различимы ли рекомендация и предложение, видны ли демометки, понятны ли next action и конфликт версии?

Фиксировать согласование по каждой области: дата, reviewer, версия контракта/commit, решение и оставшиеся разногласия. Пока подтверждений нет. Изменение контрактов требует отдельного согласования с владельцем; документ не разрешает менять чужой модуль.
