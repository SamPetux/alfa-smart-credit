# Объяснения и ИИ: варианты (B11+)

Требование кейса: LLM только с **открытыми весами**; платный runtime API запрещён.  
В P0 команда сознательно без LLM: reason_codes + шаблоны. Ниже — что можно и что уже сделано.

## Варианты

| Вариант | Скорость внедрения | Качество | Риск | Рекомендация |
|---|---|---|---|---|
| **A. Шаблонный помощник** по `reason_codes` + статус | Часы | Предсказуемо, воспроизводимо | Низкий | **Сделано сейчас** (`GET …/explain`) |
| **B. Расширенные шаблоны** (next step, FAQ по кодам) | 0.5–1 день | Лучше UX без модели | Низкий | Итерации поверх A |
| **C. Локальная tiny LLM** (Ollama / llama.cpp, 1–3B Q4) | 1–3 дня + вес модели ~1–2 ГБ | Живой текст | Тяжёлый образ, RAM, недетерминизм, GPU optional | Только P1 после стабильного UI |
| **D. Платный API (OpenAI и т.п.)** | Быстро | Высокое | **Запрещено** кейсом для runtime | Не делать |
| **E. Autономный LLM-андеррайтер** | — | — | Нарушает «score ≠ решение» | Запрещено |

## Что реализовано

`GET /api/v1/applications/{id}/explain?topic=general|why|next|amount`

- Движок: `template-v1`, `uses_llm: false`
- Берёт статус заявки и `reason_codes` активного risk run
- Тексты из `backend/app/risk/explanations.py` + next-step по статусу
- Не меняет статус и не предлагает обход OFFICER

## Если позже захотим open-weight LLM (C)

Минимально безопасный контур:

1. Отдельный optional сервис `EXPLAIN_LLM_URL` (localhost Ollama), default **выключен**.
2. Промпт только: статус, reason_codes, уже готовые шаблонные bullets — **без** сырых документов и ПДн.
3. Ответ модели = paraphrase; финальный экран всегда показывает и шаблоны, и пометку «сгенерировано локальной моделью».
4. Таймаут 2–3 с → fallback на шаблоны.
5. Compose profile `llm` не входит в обязательный `docker compose up`.

Пока UI нет, вариант C не даёт ценности на защите; A достаточно для «почему такой ответ».
