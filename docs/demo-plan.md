# D08 — план защиты (P0 к сдаче)

Подготовил Дмитрий; актуализация 2026-10-26 под полный стек. Регламент жюри может отличаться — подстроить тайминг на месте.

## Порядок рассказа (~8–10 мин)

1. **Проблема** (1 мин): подготовка заявки и рассмотрение досье; H01–H04 — гипотезы, не доказанная экономия.
2. **Решение** (1 мин): два кабинета, сохранённая заявка, локальные симуляторы, score отдельно от policy; OFFICER подтверждает финал.
3. **Живое демо UI** (4–5 мин), профиль `DEMO-001` (happy path):
   - клиент: черновик → документы → отправка → ожидание;
   - банк: очередь → досье → approve;
   - клиент: условия/платёж → принять → имитация подписи → `COMPLETED`.
   - Опционально 30 с: `DEMO-002` / отказ или альтернатива — не уходить в детали кода.
4. **Объяснимость** (1 мин): показать reason_codes / «учебная оценка»; candidate ≠ предложение банка.
5. **Надёжность** (1 мин): idempotency, CSRF header, stale job; указать на `docs/qa/readiness-report.md`.
6. **Ограничения** (30 с): синтетика, имитация выдачи, без LLM, гипотезы не измерены.

## Подготовка показа

```bash
docker compose up --build -d
# UI: http://127.0.0.1:8080/
# Готовность: curl -s http://127.0.0.1:8080/ready
```

Чеклист до выхода: seed профили видны; worker жив; cookie demo session; не показывать секреты/env. Если сервис упал — назвать сбой и показать сохранённый отчёт QA, не импровизировать «всё работает».

Запасной сценарий без UI: Postman `docs/qa/postman/alfa-smart-credit.postman_collection.json` (E01 API).
